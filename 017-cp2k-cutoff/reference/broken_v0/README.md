# 017 invalid benchmark — 坏版本冻结(v0)

> 修复前的坏版本存档。修复后此文件保留,用于解释"为什么修"。

## 根因

```
REF_ENERGY = -17.219495884120  ← 被错误标注为 E(CUTOFF=500)
```

但用最终评测镜像 `dftworld-base-cp2k`(CP2K 2025.2)实跑:

| CUTOFF | REL_CUTOFF | E (Ha) | 与坏 REF 差 |
|-------:|-----------:|-------:|------------:|
| 200 | 默认 40 | **-17.21949588411158** | **≈ 8e-12(与 REF 逐位吻合)** |
| 280 | 默认 40 | -17.21979251133290 | 2.97e-4 |
| 320 | 默认 40 | -17.21977721551897 | 2.81e-4 |
| 500 | 60 | -17.21966955233189 | 1.74e-4 |
| 600 | 默认 40 | -17.21966526388816 | 1.69e-4 |

**结论**:REF_ENERGY 实际等于本环境 E(CUTOFF=200),却标注成 E(CUTOFF=500)。

即 benchmark 的 reference 是用**原模板 CUTOFF=200** 算的,不是 500。
guide / tests / runtime 数值不自洽。

## 推论

1. guide 声称 "320 → 7.8e-6 达标",但本环境 E320 真实误差 2.8e-4,不达标。
2. 本环境唯一接近坏 REF 的 CUTOFF 恰是 200(原模板);而 tests 又强制要求改到 320。
   → `CUTOFF=320` 与 `|E-REF|<1e-4` 在本环境**不可能同时满足**,Agent 无合法解。
3. 已排除 REL_CUTOFF 假设:CUTOFF=320 下 REL 40 vs 60 能量差 5e-8 Ha,均远偏离 REF。
   真正的运行时收敛值 ≈ -17.219665(500/600 Ry),系统性偏离坏 REF 1.7e-4。

## Agent 执行正确性

Agent 读 guide → 选 320 → 改 H2O.inp → 跑 CP2K → 提取能量,全部正确。
失败完全由 benchmark 自身数值不自洽导致,非 Agent 错误。
