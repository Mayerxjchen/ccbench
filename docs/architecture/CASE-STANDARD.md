# Case Contract Standard (v0)

**Status:** Normative. Owns the case manifest, allowlist packaging, legacy
compatibility, case versioning, and digest rules.

## Execution class

```python
execution_classes = {"local_sandbox", "hpc_controller"}
```

- `local_sandbox` — scientific computation runs inside the Candidate sandbox
  (37 current cases).
- `hpc_controller` — the Candidate controls scientific computation on an
  evaluator-provided HPC site through `bench-hpc` (Cases 031–034).

**Rules:**

- Execution class is **never inferred from a case number or directory name**.
- Cases 031–034 must explicitly declare `hpc_controller`; all others resolve
  explicitly or compatibly to `local_sandbox`.
- The legacy value `real_hpc_controller` is accepted **only** through the
  explicit compatibility mapping `real_hpc_controller -> hpc_controller`, and
  the normalization is recorded in run-record provenance.
- A manifest is rejected if both `task.toml` and `task.yaml` exist.

## Case manifest

- Canonical form is `task.yaml` (schema v2); `task.toml` (schema v1.2) is
  accepted during migration. The loader never mixes them.
- `schema_version`, `case_id`, and `case_version` are required.
- `[execution].class` chooses the execution class.
- For `hpc_controller`, an `[hpc]` object is required (contract version,
  required capabilities); for `local_sandbox` in canonical v2 it is rejected.

## Generated Drafts (Case Factory)

Draft Cases produced by `dftworld_bench.case_factory` declare:

- `schema_version = "1.2"`, explicit `case_version`, and an explicit
  `[execution].class` (never inferred from the directory name).
- `[candidate].submission_root = "final"` and
  `legacy_submission_layout = false` — Drafts use the canonical `final/`
  submission layout, never legacy root layout.
- A `[generated]` table (runtime-ignored) recording `target`, `adapter_version`
  and `design_sha256` so the executable manifest is traceable to its source
  `case-design.yaml`.
- Generated bytes are deterministic; timestamps never participate in digests.
  Drift is detected by recomputing expected bytes, never by trusting rendered
  output.
- Adapter rendering never touches instruction, public, source science,
  reference, solution, tests, profiles or evidence; those are authored,
  not generated.

## Candidate bundle (allowlist packaging)

- Built by **positive allowlist only**; never copy a whole case and delete
  private paths.
- `[candidate].instruction` maps the case-relative instruction source to the
  Candidate-relative `instruction.md`.
- Each `[[candidate.files]]` rule is `{source, destination, strip_prefix?}` —
  an explicit case-relative source mapped to a Candidate-relative destination,
  so legacy `/app/<file>` paths stay stable without parsing a Dockerfile.
- Glob sources resolve under the case root; symlinks and non-regular files are
  rejected; destination collisions are rejected; normalized destinations are
  sorted.
- The bundle manifest records normalized relative paths, byte sizes, lowercase
  SHA-256 values, case/schema versions, and a deterministic root digest over
  `<sha256>  <size>  <normalized-relative-path>` lines.
- Forbidden-name leak scan: `reference`, `solution`, `tests`, `verifier`,
  `thresholds`, `fixtures`, `.git`, `expert_notes`.

## Submission layout

- Canonical v2 cases write `final/`.
- Legacy cases whose instructions require outputs directly under `/app` declare
  `submission_root = "."` and `legacy_submission_layout = true`; the collector
  removes runtime-only names and records the legacy layout in provenance.
- Moving an old case to `final/` is a **case-version increment**, not part of
  the infrastructure-only refactor.

## Case versioning

- Changing instructions, references, thresholds, hidden fixtures, or expert
  solutions requires a new `case_version` and invalidates prior comparison.
- Infrastructure-only changes (manifest shape, packaging, verifier plumbing)
  keep the case version and are recorded at the release level.
