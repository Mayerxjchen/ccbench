# 计算化学案例构造与评测：031–034 增补设计

## 目标

在保留现有周报版式和章节逻辑的前提下，补充 031–034 的任务内容、研究级难度和发布状态，并用清晰的图文解释长时计算任务为什么采用 Sandbox 控制层、如何受控访问 HPC、如何保留可验证的执行证据。

## 信息口径

- 031–033：以当前案例目录中的 `instruction.md`、`task.toml`、`VALIDATION.json` 和 `benchmark_valid.json` 为准；三例 paper profile 与发布门禁均已通过。
- 034：以 `034-hpc-controller` 工作树中的正式构造快照为准；案例仍为 `benchmark_valid=false`，不得写成已发布或已完整验证。
- 不把调度器 `COMPLETED` 等同于科学成功；科学结果必须继续通过计算输出解析和 hidden verifier。

## 文档改动

1. 更新“本周结论”“案例梯度”“下一步计划”和附录状态，消除 031–033 仍待 GPU 标定的旧表述。
2. 新增“研究级案例 031–034”章节：每个案例包含任务目标、主要执行链、核心交付物、难点和当前状态。
3. 新增“长任务为什么放在 Sandbox”说明：隔离秘密、限制权限、保护凭证和集群、避免长任务在候选容器内失控，同时保证不同 Agent 的资源边界一致。
4. 新增“受控 HPC 执行”流程图：Agent/Sandbox → HPC Controller → 白名单 SSH/传输/Slurm → 远端专属工作目录 → 状态与产物回传 → Candidate 销毁 → 独立 Verifier。
5. 新增分阶段技术路线：发现能力、准备输入、预检、提交、监控/续跑、回传、清洗、验证；每阶段明确控制点和证据。
6. 用 034 的 CP2K AIMD → DeePMD → 主动学习 → 独立可靠性验证作为长任务示例，并说明 031–033 的 MatClaw 任务如何复用同一控制思想。

## 表达与版式

- 延续原文档的蓝色标题、浅色流程框、图注、表格和页脚，不引入第二套视觉系统。
- 流程图以少量节点和短语呈现；正文解释细节，避免把长段文字塞入图框。
- 状态统一使用“已通过门禁”“构造中/未验证”等明确措辞，不混用“smoke 通过”与“benchmark_valid”。
- 生成增补版副本，不覆盖原文件；最终逐页渲染检查文字溢出、图形错位、表格跨页和页码。

- 明确说明控制器不是给 Agent 任意 SSH 权限，而是对主机、操作、参数、路径和作业生命周期进行约束。
- 034 不被误写为已完成验证；031–033 不再被误写为待 paper profile。
- 最终 DOCX 可正常打开，所有页面渲染无重叠、裁切或破损。
